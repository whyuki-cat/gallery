# Proposal

## Why

项目已经有可用的文件浏览与重命名工具，但视频裁剪仍是占位页。用户经常需要从长视频中取出若干片段，重新编码既慢又会损失画质，因此需要一个本地、快速、无损的裁剪工具：选定区间后直接按流复制导出，不等待转码，也不改变原始画质。

第一版只做无损切割，输出固定到源文件同目录，先覆盖最常见的“从本地视频截取几个片段”的场景。

## What Changes

- 新增 `/tools/trim` 页面，替换现有占位页：
  - 左侧为视频预览、自定义播放控件与时间轴，右侧为片段列表、输出预览与导出按钮。
  - 视频不使用原生播放控件，按原始比例铺满可用区域；提供播放/暂停、前后 1 秒与时间码。
  - 点击或拖动时间轴只定位播放头，不自动设置边界。
  - 通过“设为起点 / 设为终点”按钮按当前播放头显式标记，支持 `I` / `O` 快捷键。
  - 片段按时间展示起点、终点、时长，可删除；存在重叠时提示合并后会重复。
- 新增服务端无损导出接口 `POST /api/trim/export`：
  - `output: separate` 逐段导出为独立文件；
  - `output: merged` 先导出临时分段，再通过 FFmpeg concat demuxer 合并为一个文件。
- 输出文件固定写入源文件所在目录，由服务端生成名称：
  - 逐段：`<原名>-<起点时间>-<终点时间>.<扩展名>`，时间格式为 `HH.MM.SS.mmm`；
  - 合并：`<原名>.trimmed.<扩展名>`；
  - 目标重名时自动追加 `(1)`，不覆盖已有文件。
- 新增共享的片段校验、时间格式化与输出命名纯函数，前端预览与服务端执行使用同一份规则。
- 没有 FFmpeg 时通过能力探测禁用导出并提示原因；视频仍可预览和标记。
- 更新 README 与路线图，补充导出接口、临时目录与能力字段。

明确不在本次范围内：

- 不做重新编码、转码或画质/码率设置；所有导出均为 `-c copy`。
- 不保留字幕与多音轨，只复制第一条视频流与第一条音频流。
- 不支持自定义输出目录，不提供任务队列、进度条或后台导出。
- 不引入 `ffprobe`，视频时长由浏览器 `<video>` 元数据提供。
- 不修改现有文件浏览与重命名能力的行为。

## Capabilities

### New Capabilities

- `video-trimmer`: 本地视频无损裁剪。覆盖视频选择、时间轴标记、片段管理、逐段与合并导出、输出命名与冲突处理、路径安全校验，以及 FFmpeg 缺失时的能力降级。

### Modified Capabilities

无。

## Impact

- **共享包** `packages/core`：新增 `trim` 类型、片段校验、时间格式化与输出命名函数，保持纯函数、无 I/O。
- **后端** `apps/server`：新增 `/api/trim/export` 路由与导出服务；从缩略图模块抽出 FFmpeg 路径与能力探测；`/api/fs/roots` 增加 `capabilities.ffmpeg`；合并临时文件写入 `data/tmp/`。
- **前端** `apps/web`：`/tools/trim` 由占位页替换为真实页面，新增 `features/trim` 组件与视频选择弹窗；`App.tsx` 注册路由，`lib/api.ts` 增加导出请求。
- **数据**：运行时临时文件位于 `data/tmp/trim-*`，成功后清理；`data/` 已在 `.gitignore` 中忽略。
- **依赖**：不新增运行时依赖，继续使用已有的 `ffmpeg-static`。
- **安全**：复用绝对路径校验、符号链接拒绝与 `x-gallery-client` 请求头校验；服务端只接受源文件路径与时间区间，输出名称由服务端生成。
