# Proposal

## Why

媒体管理器目前只有导航骨架和占位页，没有任何可用的工具。整理本地媒体时最先遇到的机械劳动就是改名：同一批下载的文件往往带着站点前缀、分辨率标记、多余的点号和大小写混乱。手工逐个改名既慢又容易出错，而现有系统没有任何访问磁盘的入口。

因此先落地「文件重命名」这一独立工具：它不依赖 ffmpeg、不依赖媒体库，能立刻投入使用，同时为后续的媒体库扫描复用同一套文件系统访问层。

## What Changes

- 新增工具页 `/tools/rename`（替换现有占位页），页面本身即文件浏览器：顶部路径栏与面包屑，下方文件区。
- 新增后端文件系统访问层：盘符/常用目录枚举、目录列表、按需批量 `stat`、原文件读取、缩略图。
- 新增纯函数重命名引擎（独立工作区包），提供有序规则链、模板变量、文件名合法性与冲突校验。前后端共用同一份实现：前端负责实时预览，后端负责执行前重算与校验。
- 新增重命名执行能力：两阶段改名（先临时名再终名）以正确处理交换与仅大小写变更，失败时按已完成步骤回滚。
- 新增操作日志与撤销：append-only JSONL 记录，支持回滚最近一次操作。
- 新增文件详情：路径、大小、时间、类型；图片预览直接读取，视频首帧与媒体信息在缺失 ffmpeg 时降级隐藏。
- 新增列表/网格双视图、排序、筛选、搜索与多选交互，视图偏好本地持久化。

明确不在本次范围内：

- 不重命名子目录，不跨目录移动文件，不创建或删除文件。
- 不做媒体元数据改名（标题、年份、`SxxEyy`），不引入 ffprobe 依赖。
- 不做文件内容预览以外的播放、转码或媒体库扫描。

## Capabilities

### New Capabilities

- `file-browser`: 本地目录导航与文件展示。覆盖路径解析与导航、目录枚举、文件元数据、列表与网格视图、排序筛选搜索、多选、文件详情与图片预览。
- `file-renamer`: 基于规则的批量重命名。覆盖规则链求值、模板变量、目标名合法性与冲突校验、执行策略、失败回滚、操作日志与撤销。

### Modified Capabilities

无。

## Impact

- **新增工作区包** `packages/core`：重命名规则引擎与校验器，纯函数、无 I/O，可独立单测；`apps/web` 与 `apps/server` 共同依赖。
- **后端** `apps/server`：新增 `/api/fs/*` 与 `/api/rename/*` 路由，新增文件系统访问与 JSONL 日志模块；`app.ts` 需注册新路由。
- **前端** `apps/web`：`/tools/rename` 由占位页替换为真实页面，新增 `features/rename` 组件集合；`lib/nav.ts` 无需改动。
- **数据**：运行时日志写入 `data/rename-log/*.jsonl`，该目录已在 `.gitignore` 中。本次不引入数据库。
- **安全**：服务仅监听 `127.0.0.1`；所有路径在服务端 `resolve` 后校验，拒绝路径穿越，默认不跟随符号链接。
- **外部依赖**：无新增运行时依赖用于改名；ffmpeg 为可选能力，缺失时相关 UI 降级而非报错。
